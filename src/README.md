# The mod implementation

Builds against **SPT 4.1.x** / .NET 10.

| File | Role |
|---|---|
| `FleaPriceLevelScalingMod.cs` | `IOnLoad` + `IOnUpdate`. Resolves the active profile, applies prices, regenerates the flea. |
| `PriceTable.cs` | Loads the day-indexed curves and bakes them down to per-level prices. |
| `FleaNoise.cs` | Stateless market price walk. Port of `analysis/fleanoise.py`. |
| `Config.cs` | Two-tier config with range clamping. |
| `FleaPriceLevelScalingMetadata.cs` | SPT mod manifest. |
| `config.jsonc` | User-editable settings. |
| `data/price_curves.json` | Generated by `analysis/07_build_trend_curves.py`. |

## How it works

`OnLoadAsync` reads the config, loads the table, disables SPT's own flea pricing (`ragfairConfig.Dynamic.GenerateBaseFleaPrices.UseHandbookPrice = false`), clones the original price table for bounds and applies prices once.

`OnUpdateAsync` re-checks every 120 seconds and returns immediately unless the level, the wall-clock hour or the active profile changed. When something did change it reprices and regenerates the dynamic flea offers.

Price for one item:

```
// Two-phase level -> season day mapping:
if (level <= fleaUnlockLevel)
    day = startDay
else if (level <= troughLevel)
    day = startDay + (level - fleaUnlockLevel) / (troughLevel - fleaUnlockLevel) * (troughDay - startDay)
else if (level <= scalingMaxLevel)
    day = troughDay + (level - troughLevel) / (scalingMaxLevel - troughLevel) * (endDay - troughDay)
else
    day = endDay

base   = interp(dayKnots, price[item], day)
anchor = interp(dayKnots, price[item], startDay)

trend  = anchor * (base / anchor) ^ intensityExponent      // baked once at load
final  = trend * exp(min(sigma * amplitudeScale, sigmaCap) * Z(item, hour, world))
final  = clamp(final, sptBase * bounds.min, sptBase * bounds.max)
```


1. **`intensityExponent` applies to the ratio.** Raising the whole product would scale the base price too and would exponentiate the noise at k=2 a 1.5x spike becomes 2.25x.
2. **`debug.priceBounds` (`min` and `max`) clamp against SPT's table.** On load, the mod clones `templateTable.Prices` before modifying anything. Every calculated price is clamped to `[sptBase * min, sptBase * max]` (defaults `0.2` and `5.0`, or 20%–500% of the vanilla SPT price). This ensures market shocks or volatile curves never drift into absurd extremes while preserving natural market movement within that envelope.
3. **`troughLevel` defines at which player level the initial price crash bottoms out.** Spans levels `fleaUnlockLevel` -> `troughLevel` across `startDay` -> `troughDay` (default 41.9). Raising it softens and elongates the early-wipe price drop.
4. **`scalingMaxLevel` defines at which player level the price curves end.** Above it, prices resolve to `endDay` and the trend stays flat. SPT's maximum player level (79) is still fully supported: levels from `scalingMaxLevel` up to 79 (including) plateau at that end-of-season price, while the hourly price walk continues to drift on top.

Items absent from the table (`pegged` and `sparse`, ~700) keep SPT's default price.

## Profile access

Read-only. `ProfileActivityService.GetActiveProfileIdsWithinMinutes(30)` finds all actively playing profiles and selects the PMC with the highest level. If no player is currently active, the mod falls back to the single profile on disk if exactly one exists (standard single-player setup). When multiple profiles exist (FIKA / multi-character installs), it starts at baseline level 15 and waits for an active player before scaling.

This ensures seamless support for both local single-player setups and multiplayer / FIKA servers:
- **Server boot (offline):** If exactly one profile exists, base flea prices are anchored to that character's level immediately; if multiple exist, the server waits for an active session.
- **Solo play:** When a player logs in, the flea market smoothly adapts to their active level.
- **FIKA co-op:** When multiple friends play concurrently, flea prices scale to the highest level among all currently active players.

From the resolved PMC the mod reads `Info.Level`, plus `_id` and `Info.RegistrationDate` for the per-playthrough market seed.

### Player flea listings

They live on the profile at `PmcData.RagfairInfo.Offers` and are persisted by `SaveServer`, so they survive a restart. Only the generated PMC offers are rebuilt each start.

`RegenerateRagfair` therefore has to be careful:

1. It skips `IsTraderOffer()` and `IsPlayerOffer()` when flagging offers expired. `RagfairOfferHolder.GetStaleOfferIds()` only returns ids added by `FlagOfferAsExpired`.
2. SPT's `ProcessStaleOffer` is destructive: `ReturnUnsoldPlayerOffer` edits `RagfairInfo.Offers` and mails the items and docks rep when `staleOffer.EndTime <= now`.

### Listing fees are affected

`RagfairTaxService.CalculateItemWorth` calls `ragfairPriceService.GetFleaPriceForItem`, which reads the same price table this mod rewrites. Listing fees therefore scale with level alongside prices.
